# Xuxuan Profile — 网站可编辑能力设计方案

**日期：** 2026-08-24
**状态：** 已确认

---

## 概述

当前网站为纯静态展示站：所有图文内容硬编码在 `index.html` 的 `profileData` 对象里，要改内容必须手动改代码并 `git push`。

本方案为网站增加「可写」能力：站长（本人）可以在网页里直接新增/编辑/删除事件、上传图片，点「保存并发布」后自动提交到 GitHub 仓库，GitHub Pages 自动重新发布，所有访客约几十秒后可见。访客仍只能看、不能改。

---

## 需求边界

**谁能看：** 所有访客。

**谁能改：** 仅站长本人（通过一把只授权本仓库的 GitHub Token 解锁）。

**可编辑的范围：** 仅「事件」层——即点进某个最小板块（如「学科竞赛」「志愿者」）之后的图片 + 文字（标题、描述、备注、封面、排版、图片多张）。

**明确不可编辑（非目标）：**
- 板块名/板块增删（「学科竞赛」这些板块本身）
- 页面名（高中/大学）、首页文案、封面标题、导航
- 不新增板块、不新增页面

---

## 技术方案

采用 **GitHub Contents API 直接提交** 的方式（做法一）：

1. **内容抽离**：图文从 `index.html` 抽到独立 `data.json`；`index.html` 打开时 fetch `data.json` 渲染，失败则回退到写死在 `index.html` 里的初始内容兜底。
2. **编辑模式**：首页角落小「编辑」按钮解锁；进入最小板块后出现增删改控件。
3. **发布**：点「保存并发布」，网页用 Token 通过 GitHub API 把新图片 + 新 `data.json` 提交到 `main` 分支；Pages 自动重新构建。

优点：免费、无第三方依赖、图片归本人所有、以后迁到自有服务器可直接复用 `data.json`。

---

## 数据模型

`data.json` 结构与现有 `profileData` 一致，仅在每个事件上新增唯一 `id`：

```json
{
  "highschool": {
    "name": "高中",
    "grid": "grid-2x2",
    "sections": [
      {
        "id": "hs-competition",
        "name": "学科竞赛",
        "desc": "竞赛 · 获奖情况",
        "events": [
          {
            "id": "evt_xxxxxxxx",
            "title": "第41届全国中学生物理竞赛",
            "desc": "……",
            "imgs": ["images/82eebb….jpg"],
            "caption": "第41届全国中学生物理竞赛·上海",
            "cover": "",
            "layout": "split"
          }
        ]
      }
    ]
  },
  "university": { "…": "…" }
}
```

- `id`（事件级）：编辑时精确定位「改的是哪个事件」，新增事件时生成。
- `layout`：详情页排版，`split` = 左图右文，空 = 上图下文（沿用现有能力）。
- 其余字段语义与现有 `ev()` 一致。

## 编辑界面

**入口：** 首页右下角小「编辑」圆点（半透明、不显眼）。

**解锁：** 首次点击弹出输入框，粘贴一次 GitHub Token；存于浏览器 localStorage，此后免粘贴。访客无此入口、无 Token，无法进入编辑模式。

**编辑模式（进入最小板块的二级网格后）：**
- 板块顶部出现 `＋ 新增事件`。
- 每个事件卡片上出现 `编辑` / `删除` 小按钮。

**事件表单字段：**

| 字段 | 说明 |
|---|---|
| 标题 | 事件标题 |
| 描述 | 正文（原「待补充」内容） |
| 图片 | 可多张，支持排序、删除、指定封面 |
| 备注 | 卡片下方小字（如「赛后合影」） |
| 排版 | 上图下文 / 左图右文 |

**保存：**
- 顶部/底部常驻提示条 `编辑模式中 · [保存并发布]`。
- 未点发布前，改动仅暂存本地，不影响访客看到的网站。

## 图片处理

- **上传即压缩**：浏览器端把图片最长边缩到约 1600px、转压缩格式（目标 200~500KB），以满足 GitHub API 单文件 1MB 上限并提升加载速度。
- **命名**：唯一随机文件名（沿用现有 `images/` 命名风格），避免覆盖。
- **存储**：`images/` 目录。
- **删除**：从事件移除的图片同步从仓库删除，不留垃圾。
- **取舍**：存的是压缩版而非手机原图；如需原图级高清展示，留待未来有服务器时实现。

## 发布流程与安全

**Token（钥匙）：**
- 类型：GitHub Fine-grained Personal Access Token。
- 授权范围：仅 `xuxuan-profile` 一个仓库 + `Contents` 读写权限。
- 存放：仅站长浏览器 localStorage，不写入仓库、不发给他人。
- 撤销：泄露时在 GitHub 撤销并重新生成即可。

**发布时序：**
```
点 [保存并发布]
  → 打包改动（新图片 + 新 data.json）
  → 用 Token 经 GitHub API 提交到 main 分支（一次提交，说明如 "Update content via editor"）
  → GitHub Pages 重新构建
  → 约几十秒~1 分钟，所有访客刷新可见
```

**边界情况：**
- 首次使用、`data.json` 不存在：自动用 `index.html` 内现有内容初始化首个 `data.json` 一并提交，内容不丢。
- 多设备/冲突：保存前核对仓库最新版本，不一致则提示「先刷新再保存」。
- 加载兜底：`data.json` 读取失败时回退 `index.html` 内嵌内容，永不白屏。

## 测试要点

- 首次初始化：无 `data.json` 时正常兜底渲染 + 首发布生成。
- 新增/编辑/删除事件，多图排序、封面指定、排版切换。
- 图片压缩后 < 1MB 且上传成功。
- 发布成功后访客视角（无 Token）可见新内容、且无法编辑。
- 兜底路径：临时移除 `data.json`，页面仍能渲染初始内容。
